# 73: Keycloak: remove customers, TOTP on portals, private_key_jwt for partners

**What to build:** The Keycloak part of spec 18.2 (D21, S14).

- **Remove** the `customers` realm (`deploy/keycloak/realms/`), its APISIX token route (`deploy/apisix/routes/auth-customers-token.json`), `KC_CUSTOMERS_TEST_PASSWORD` from `deploy/dev.env.defaults`, and every use in the seeder, test console, Newman collection (`node tests/api/build_collection.mjs`), Playwright, `scripts/creds.sh`, `docs/testing-guide.html` and the tutorial.
- **portals:**
  - TOTP required (the `browser-mfa` flow as in `ops`);
  - seeded org users get a pre-set TOTP secret (fake, documented) so `scripts/totp.sh` can print codes for them;
  - the portal e2e and Newman logins use it.
- **partners:**
  - `partner-sim` authenticates with `private_key_jwt` (key pair generated by provisioning; the private key in OpenBao KV for the simulator);
  - no client secret.
- **Every realm:** brute-force detection (permanent lockout off, wait increment on), a password policy (length 12, not username, history 5), and the token lifetimes reviewed.
- Update `docs/adr/D9-platform-services.md` (realm list amendment).
