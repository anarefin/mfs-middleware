Wallet auth page: step-by-step guide

How to use the test console's https://localhost/tester/auth. The page tests wallet authentication at mw-auth: OTP, device binding, PIN login, a second device, PIN change, the self-service and care PIN resets, and the lockout. Ticket 76.

Before you start

  • Start the stack with the tester profile and the default dev.env.defaults timers. From deploy/, run:
    docker compose --profile core --profile seed --profile tester up -d --build --wait
  • The page works only on fresh wallets it creates itself: core-mock customers 01711000500..01711000999 that have no app PIN yet. It never touches the seeded users (PIN 13579).
  • Keep the same wallet through steps 2–7. The Wallet field holds it. The console keeps the wallet's state (device key, tokens) in memory: if the console restarts, create a fresh wallet again.
  • The How to test panel at the top has fill buttons: Good PINs (48207 / 61938), Weak first PIN 11111 and Reset to 73052.

Page layout

1. A fresh walletfirst PIN, Create, Wallet field
2. Log in, second devicePIN, Log in, Bind a second device
3. Change or reset the PINcurrent/new PIN, NID last 4, DOB, three buttons
4. LockoutThree wrong PINs
mw-auth (result) A headline, then every HTTP call as a step: label, call, status, redacted body and time in ms. Click a step to expand it. A ✖ marks a step that failed.

1Create a fresh wallet

  1. In panel 1, set First PIN to 48207 (the default).
  2. Press Create a fresh wallet.
pick a free customer → LOGIN OTP (read from the SMSC simulator) → bind the device (EC key) → set the first PIN
Expect"fresh wallet 01711000xyz ready: device bound, first PIN set (amr …)". The Wallet field fills in with the number.
NegativeA weak first PIN is refused with 400 MW-AUTH-044. Weak PINs are 11111 (REPEATED_DIGIT), 34567 (SEQUENCE) and the wallet's last five digits (MSISDN_DIGITS).

2Log in with the PIN

  1. In panel 2, leave PIN at 48207.
  2. Press Log in with the PIN.
Expect"logged in: amr …pin, device <id>, token N s".
NegativeWith a wrong PIN, the headline shows "refused MW-AUTH-040: N tries left".

3Bind a second device

  1. In panel 2, press Bind a second device. The PIN in the field is used.
new phone: BIND OTP → bind (key + OTP + PIN) → old phone: log in (refused) → old phone: refresh (refused) → new phone: log in
Expect
  • "second device … bound at …; cooling (newDevice) until <boundAt + 24 h>; the old device is out".
  • The old phone's steps answer 401 MW-AUTH-047.
  • An SMS about the new device. Check it in the console's Inbox page.
A wallet has only one bound device. For 24 h, its transaction assertions to the core carry newDevice=true. The page only shows the window: the flag itself travels only in the signed assertion.

4Change the PIN

  1. In panel 3, set Current PIN to 48207 and New PIN to 61938.
  2. Press Change PIN. If there is no session, the console logs in first.
  3. In panel 2, log in with 48207: it is refused. Then log in with 61938: it works.
Expect"PIN changed; the session is replaced (old refresh token revoked)" and a "PIN changed" SMS.
NegativeA new PIN equal to the current one is refused with 400 MW-AUTH-044 (LAST_PIN). After this step, the current PIN is 61938: update the PIN fields before the next steps.

5Self-service PIN reset

  1. In panel 3, set New PIN to 73052, NID last 4 to 4821 and Date of birth to 1990-05-17. The Reset to 73052 fill button sets all of these.
  2. Press Self-service reset.
  3. In panel 2, log in with 73052.
RESET OTP on the bound device → open the reset (202) → poll while PENDING_KYC (the core checks NID + DOB) → VERIFIED → set the new PIN
Expect"self-service reset <id> DONE: new PIN set, every session ended, PIN lock cleared". The login with the new PIN works.
NegativeOnly the bound device may ask a reset OTP. If the core does not verify the factors, the page stops with "the core did not verify the factors".

6Take up a care reset on a new phone

A care reset is for a customer who lost the phone. Ops approves it first, in the ops console with maker-checker.

  1. Open /console, Wallets, and sign in as seed-ops-maker. Request PIN reset for the wallet's number. To get the one-time code, use the console's Logins & secrets page or scripts/totp.sh seed-ops-maker.
  2. Sign in as seed-ops-checker and approve the request. The wallet gets the SMS "Your Bits PIN reset was approved…".
  3. Back on the auth page, set a New PIN in panel 3 (for example 73052). Press Take up a care reset (new phone).
new phone: RESET OTP → take up the reset → set the new PIN → BIND OTP → bind the new phone with the new PIN
Expect"care reset <id> DONE on the new phone; it is bound with the new PIN".
NegativeBefore the approval, the new phone's reset OTP is refused with 403 MW-AUTH-002. The page says "no reset OTP: is the care reset approved in the ops console?".

7Lockout

  1. In panel 4, press Three wrong PINs (MW_AUTH_LOCK_TRIES). The console sends 97531 three times.
  2. In panel 2, press Log in with the PIN with the right PIN.
Expect
  • Wrong PINs 1 and 2: 401 MW-AUTH-040, with 2 and then 1 tries left.
  • Wrong PIN 3: 423 MW-AUTH-041 with retryAfter, at most 60 s with the dev timer MW_AUTH_LOCK_LEVEL1=1m.
  • The right PIN is then refused the same way ("refused MW-AUTH-041"), without being checked.
To unlock, do one of these:
  • Wait out the lock.
  • In /console Wallets, an ops-maker requests the unlock and an ops-checker approves it (testing guide 9.8).
  • Use the Unlock row tool on the console's Seed data page (testing guide 1.5).
If three more wrong PINs come after the first lock, the lock goes to level 2 (MW_AUTH_LOCK_LEVEL2=3m). After that it is permanent (MW-AUTH-042) until a PIN reset.
