The building blocks, one at a time

You know Spring Boot and Kafka. This guide covers everything else the middleware leans on: the gateway in front, the login and secret servers beside it, the fake HSM, the doubles that stand in for the core and the partners, and the libraries inside every service. Each page explains one component and how this project uses it, with a real example from the repository.

How this differs from the tutorial

The tutorial follows the business: money flows, partners, ops. It mentions APISIX, Keycloak and Vault in a few lines each. These pages go the other way round. They take one component, open it up, and show its config files, the classes that use it, one request from start to end, and the usual mistakes with it. Read the tutorial's chapters 1 to 3 first if the words saga, outbox or core are new.

How every page is laid out

All pages follow the same order, so you always know where to look:

  1. In plain English: what the thing is, without jargon.
  2. Why we use it here: the reason, with a link to the decision record (ADR) or spec section.
  3. How it is wired: the container, its ports and profile, and the config files.
  4. Worked example: one real request or start-up, step by step, with a sequence diagram.
  5. Where it lives: the classes and files to open.
  6. What can go wrong: the usual mistakes and the fix for each.
  7. Read next: where to go deeper.

In the sequence diagrams a solid blue arrow is an HTTP call, a dashed purple arrow is a Kafka message and a dotted grey arrow is a reply.

Values on these pages

Every password, key and phone number shown here is a fixed, fake dev value from deploy/dev.env.defaults or the seed data (customers 01711000001 upward). Real values never appear in the repository. scripts/creds.sh prints the dev logins of a running stack.
