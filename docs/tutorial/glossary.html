Glossary

Every abbreviation and project word used in this tutorial, the spec and the code.

Adapter
A service that talks to one family of outside partners (mw-adapter-telco, -billpay, -bank). See chapter 5.
Agent
A shop that exchanges cash for wallet money (cash in, cash out).
APISIX
The API gateway at the edge: the only way in from outside.
AppRole
An OpenBao login method for machines: each service has its own and can read only its own secrets.
Audit trail
The append-only, hash-chained record of everything that happened (mw-audit-dw).
BDT, Tk, poisha
Bangladeshi taka. Tk 1 = 100 poisha. Amounts are stored as whole poisha in valueMinor.
Bulk disbursement
An organisation paying many wallets from one CSV file, with maker-checker.
Callback
A partner calling us later with the result of an earlier request.
Camel (Apache Camel)
An integration library used inside services for Kafka consumers, the outbox relay and partner routes.
Circuit breaker
Stops calling a partner for a while after repeated failures, so a broken partner does not drag everything down.
Command / event
A request to the core over Kafka ("PostTransfer") and its answer ("TransferPosted"). See chapter 3.
commandId
The id of one command, <txnId>:<step>. The core uses it to recognise a repeat.
Commit / release
Take held money, or give it back.
Compose profile
A named group of containers in deploy/docker-compose.yml: minimal, core, seed, tester.
Consumer group
A named Kafka reader. Each group sees every message of a topic once.
Contract
An OpenAPI file or JSON Schema in contracts/ that two services agree on. Owned by one service.
Core
The system that owns balances, the ledger, fees, limits and PINs. Not in this repo; mw-core-mock plays it.
correlationId
The id that ties together everything caused by one request (X-Correlation-Id).
Device binding
Linking an app install to a wallet with an SMS OTP and a device key, so every money request must be signed by that phone.
DLQ
Dead-letter queue: the Kafka topic where a message goes when it fails every retry, for a human to look at.
eKYC
Electronic "know your customer": identity checks. In the spec; not built in the MVP.
Fail closed
When unsure, choose the safe answer: an unclear partner reply is UNKNOWN, never FAILED.
Flow
The orchestrator's description of one transaction type's steps (P2pFlow, TopupFlow, ...).
HMAC
A signature made with a shared secret. Merchants and partners sign their requests; we sign IPNs.
Hold
Reserving money in a wallet without moving it, until a partner has done its part.
Idempotency
Doing something twice has the same effect as once. See chapter 3.
Inbox
A table of handled message ids, so a listener ignores a message it has seen.
IPN
Instant payment notification: our signed server-to-server message telling a shop an order is paid.
JSONata
An expression language for transforming JSON; used to map our partner requests to each partner's format.
Kafka
The message log all services use to talk to each other.
Keycloak / realm
The login server; a realm is one separate set of users (customers, ops, portals, services, partners).
Maker-checker
The four-eyes rule: one person asks for a risky change, a different person approves it.
MANUAL_REVIEW
The saga state where the system cannot decide safely and an operator must.
Masking
Hiding personal data in logs and screens: 0171****789.
MFS
Mobile financial services: a wallet on your phone number.
MNO
Mobile network operator (Grameenphone "gp", Robi, Banglalink "bl", Teletalk).
MSISDN
A mobile phone number, for example 01711000001.
MVP
Minimum viable product: the first version this repository builds.
OCS
Online charging system: the operator system that adds airtime.
OpenBao
The secrets vault (an open-source fork of HashiCorp Vault).
Orchestrator
mw-orchestrator: runs every transaction's saga and is the only service that commands the core.
OTP
One-time password sent by SMS (device binding, checkout).
Outbox
A table where a service writes outgoing messages in the same database transaction as its business change; a relay publishes them.
P2P
Person to person: send money.
Partner reference
The stable id we give a partner for one transaction (top-up: BITS + txnId in hex), so a repeat is recognisable.
PIN ciphertext
The PIN encrypted with the core's public key (RSA-OAEP). The middleware carries it but cannot read it.
Post
Move money in one step (PostTransfer), no hold.
Reply budget
How long a channel service waits for a final status before answering "processing" (app 25 s, USSD 8 s).
Reversal
Undoing a completed transaction with a new REVERSAL transaction, after maker-checker.
Saga
A multi-step job across systems, saved step by step, with compensating steps when a later step fails.
SagaMachine / SagaEngine
The pure decision function (state + event → next state + effects) and the part that carries the effects out.
Seeder
mw-seeder: creates the test users, wallets and balances (compose profile seed).
Simulator
mw-simulators: fakes every partner, the SMS centre, the USSD gateway and the shop's IPN receiver.
SMPP
Short message peer-to-peer: the telecom protocol for SMS and for some USSD gateways.
SMSC
SMS centre: delivers our text messages.
SP
Service provider: a business that looks up its own transactions through the portal.
SSRF
Server-side request forgery: tricking our server into calling an internal address. IPN URLs are checked against it.
Test console
mw-test-console at https://localhost/tester: plays every outside party for manual testing. Dev/test only.
Testcontainers
A library that starts real PostgreSQL and Kafka containers for *IT tests.
TOTP
Time-based one-time password: the 6-digit code from an authenticator app (ops logins). scripts/totp.sh prints it for test users.
TSQ
Transaction status query: asking the core or a partner "what happened to this transaction?" until the answer is clear.
txnId
The id of one transaction, created by the channel service and carried everywhere.
UNKNOWN
The saga state for "money may or may not have moved; we are finding out".
USSD
Unstructured supplementary service data: the text menus on any phone after dialling a code like *268#.
Valkey
An in-memory key-value store (open-source Redis): sessions, locks, counters.
Wallet
An account in the core tied to a phone number, of a type such as CUSTOMER, AGENT or MERCHANT.
