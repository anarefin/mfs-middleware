Running Bits MFS Middleware with Docker

How to start the whole middleware (14 Spring Boot services, the admin console and the platform) from deploy/docker-compose.yml on one laptop, and how to test it. This is a demo footprint for exploring the features; it is never used for load tests.

1Prerequisites

  • Docker Desktop (or Docker Engine with Compose v2.20+). Give it 8 GB of RAM: the memory limits of the full profile add up to 7.9 GB (14 JVMs, Kafka, PostgreSQL 18, Keycloak, OpenBao, Valkey, APISIX, etcd, GreenMail). Measured use is about 6 GB. 4 CPU cores or more.
  • JDK 25 on the host, to build the jars. You don't need to install Gradle: the repo ships ./gradlew.
  • For the test suites in step 11: Node.js 22+ with npx, and bash, curl, jq.
  • These host ports must be free: 443 (the edge), 8081–8093, 3000, 3001, 5432, 6379, 9094, 8180, 8200, 8025 and 3025 (step 7 says how to move one).
docker --version && docker compose version
java -version   # must report 25
node --version  # 22 or newer

2Build the service jars

The images don't compile code. Each services/<module>/Dockerfile copies build/libs/<module>.jar, so build the jars first. Run this from the repository root:

./gradlew clean build

One Gradle build: every module's tests (unit, slice, contract, Camel route, Testcontainers and conformance, in one JVM per module), every jar, and the repo checks (module isolation, no field injection, contracts lint, the compose memory budget, the shell tests). It worked when the last line is BUILD SUCCESSFUL. The Testcontainers tests need Docker running; without it they are skipped, not failed.

The build cache is on (gradle.properties). After clean, a module whose inputs did not change restores its jar and test results instead of running again. To run everything again:

./gradlew clean build --rerun-tasks   # or --no-build-cache
./gradlew clean build --continue      # list every failure, not just the first
At most 4 modules' tests run at once (mwDockerTests=4, sized for 8 cores: each runs a test JVM, a PostgreSQL and a Kafka). On a smaller host or with Docker short of memory use ./gradlew clean build -PmwDockerTests=2. Build with the stack stopped (docker compose --profile core --profile seed stop), or the test containers and the running stack compete for memory.

The two web consoles (ui/mw-admin-ui, ui/mw-test-console) are not Gradle modules: their Dockerfiles build them in step 4. Their unit tests run with pnpm, no stack needed: (cd ui/mw-admin-ui && pnpm install && pnpm test).

3Create the environment file

The .env file holds the dev credentials (database, Valkey, Keycloak admin and test users, client secrets, simulator HMAC secrets, the console session key) and the short test timers. Every container reads it. All values are fixed, obviously fake dev values committed in deploy/dev.env.defaults; deploy/.env itself is gitignored.

cd deploy
cp dev.env.defaults .env

Run every docker compose command below from inside deploy/. Compose reads .env there on its own, so no --env-file flag is needed.

The logins a tester types: ops ops-test-pass, app app-test-pass, portal portal-test-pass, Keycloak admin kc-admin-test-pass, test-route apikey e2e-test-apikey (scripts/creds.sh prints them all; testing guide, section 1).

The volumes are initialised with these values. If you change a credential in .env, reset everything (./reset.sh, step 10) before the next start.

4Start the full platform

docker compose --profile core --profile seed up -d --build

Compose builds the images (mfs-mw/<service>:local), then starts everything in dependency order. Each service waits until what it needs is healthy or has finished:

postgres · valkey · openbao · keycloak·kafka→kafka-init (topics)· etcd→etcd-init→apisix→apisix-init (routes)· provision (schemas, OpenBao secrets, AppRoles)→14 services + admin console→ mw-seeder (one-shot)
  • Always pass --profile seed with --profile core. The seeder runs once, after apisix-init has finished and every service is healthy. It goes through the services' own APIs and maker-checker, like an operator would. It is idempotent, so running the same command again is safe.
  • The short test timers (status inquiry, reversal, retry topics, IPN, partner limits) come from .env; the API suite in step 11 needs them. For the production timers, delete the "Test timers" block from .env and run docker compose --profile core up -d.
  • The provision one-shot runs on every up and creates missing database roles, schemas and OpenBao secrets, so a new service's schema appears without wiping the volumes.
  • Memory limits are knobs (APP_MEM_LIMIT, APP_XMX, KAFKA_MEM, …; the table is the header of deploy/docker-compose.yml): set one in .env to give a container more room.

On a warm Docker cache the whole command, seeding included, takes about 1–2 minutes. The first run pulls the platform images and builds 16 images, so it takes a few minutes more.

Then open the admin console at https://localhost/console. The edge certificate is self-signed for localhost, so accept the browser warning. Sign in as ops-maker01 with ops-test-pass; the first sign-in asks you to enrol TOTP with an authenticator app (scripts/totp.sh prints the code of a seeded persona).

5Wait for the seed to finish

The start command in step 4 already runs the seeder. Follow it until it exits:

docker compose --profile core --profile seed logs -f mw-seeder
docker compose --profile core --profile seed ps -a mw-seeder   # must show: exited (0)

The test suites sign in as the seeded personas, so they need mw-seeder at exited (0). What you get:

  • At start-up: mw-core-mock creates 1,000 customer wallets 01711000001…, 50 agents 01811000001…, 20 merchants 01911000001…, 2 orgs 01311000001…, all with the fake PIN 1234. Keycloak imports its realms (ops, customers, portals) with test users.
  • From mw-seeder: the personas seed-ops-maker, seed-ops-checker, seed-ops-viewer, seed-ops-compliance, seed-org-maker, seed-org-checker, seed-customer01/02, seed-agent01, seed-merchant01 with their wallets (01712000001…), the OCS partner, the USSD main menu and the P2P SMS template.

6Verify it is running

# every container should show "healthy" (init jobs and the seeder show "exited (0)")
docker compose --profile core --profile seed ps -a
# readiness of one service
curl -s localhost:8081/actuator/health/readiness
# readiness of all of them (8081-8093)
for p in $(seq 8081 8093); do printf "%s " $p; curl -s localhost:$p/actuator/health/readiness; echo; done
# the edge and the two consoles
curl -sk https://localhost/healthz
curl -s -o /dev/null -w "%{http_code}\n" localhost:3000/console/api/health
# memory and CPU per container, one service's JSON log
docker stats --no-stream
docker compose logs -f mw-orchestrator

7Services and ports

Every service listens on 8080 inside the Compose network and publishes a port on 127.0.0.1 for poking at it directly. Those direct ports skip the edge policies (JWT, HMAC, quotas, the error envelope): clients, the consoles and the test suites go through APISIX on https://localhost. To move a port that is already taken, set MW_PORT_<NAME> in .env (for example MW_PORT_POSTGRES=15432, MW_HTTPS_PORT=8443).

8Alternative: the minimal profile

To start only the P2P and cash path (the 8 services marked "minimal" above) on less RAM:

docker compose --profile minimal up -d --build

The minimal profile starts unseeded, because the seeder also seeds services that minimal doesn't run. The built-in wallets and Keycloak users are there. For a seeded stack, use the step 4 command.

9Rebuild one service after a code change

(cd .. && ./gradlew :mw-notify:build)   # its tests and jar; :mw-notify:bootJar for the jar only
docker compose --profile core up -d --build mw-notify
docker compose restart apisix            # APISIX still points at the old container's IP
# after a console change (no Gradle step)
docker compose --profile core up -d --build mw-admin-ui

10Stop and reset

# stop the containers, keep the data
docker compose --profile core --profile seed stop
# remove the containers, keep the volumes
docker compose --profile core --profile seed down
# wipe ALL state together (every volume of every profile), then start again and re-seed
./reset.sh
docker compose --profile core --profile seed up -d --build
Never reset a single store. PostgreSQL, Kafka, Valkey, OpenBao, Keycloak and the core-mock ledger describe the same state, so they are always reset together with ./reset.sh.

Run these from the repository root (cd ..) against the seeded stack from step 4.

12Troubleshooting

  • COPY build/libs/…jar fails: you skipped step 2. Run ./gradlew clean build (or ./gradlew bootJar) from the repo root.
  • A fix doesn't show up in the running stack: the images copy the jar, and --build doesn't rebuild it. Run ./gradlew bootJar first, then step 9.
  • The build passes but the *IT tests were skipped: Gradle could not reach Docker. Start Docker and run ./gradlew clean build --rerun-tasks.
  • A timing test failed once: run that class alone (./gradlew :mw-x:test --tests '*TheClassIT'). If it keeps failing on a small host, lower the test concurrency with -PmwDockerTests=2.
  • required variable … is missing a value: cp dev.env.defaults .env: you skipped step 3.
  • "port is already allocated": another process holds one of the ports in step 7 (lsof -i :5432). Stop it, or move the port with MW_PORT_<NAME> in .env. Port 443 moves with MW_HTTPS_PORT (the APIs work, the console login needs 443).
  • Containers exit with code 137: Docker is out of memory. Give Docker Desktop 8 GB, or use the minimal profile.
  • A one-shot (provision, kafka-init, etcd-init, apisix-init) exits non-zero: docker compose logs provision names the service and step. Usually volumes created with other credentials (an .env from before dev.env.defaults, or an edited value): run ./reset.sh and start again.
  • A service stays "starting": docker compose logs <service>. It is usually waiting on postgres, kafka, keycloak, openbao or provision.
  • The seeder exits non-zero: docker compose --profile core --profile seed logs mw-seeder; the line seed.step.failed names the step. open change request of <operator> means a pending request on a partner, menu or template: approve or reject it in the console, then run step 4 again.
  • 404 on /test/... routes: expected after a start; scripts/api-test.sh and scripts/tester.sh add the test-only routes.
  • Timer scenarios of the API suite fail: .env lacks the "Test timers" block. Copy it back from deploy/dev.env.defaults and run docker compose --profile core --profile seed up -d.
  • docker compose logs shows nothing for a service: services in a profile are listed only when you pass it: docker compose --profile core logs <service>.
