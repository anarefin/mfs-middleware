# Kafka topics as code (spec 6.1, 6.2), applied by the one-shot kafka-init container
# through apply-topics.sh. Single broker: replication factor 1, min.insync.replicas 1.
# The partition counts are the production reference; the dev stack overrides all of them with
# MW_KAFKA_PARTITIONS (3, deploy/compose/platform/compose.yml).
#
# Format: <topic> <partitions> <retention> [retry=<group>[,<group>...]]
#   retention: <n>d (days) or "compact" (cleanup.policy=compact)
#   retry:     for each consumer group (= the consuming service's name, its Camel Kafka
#              group-id) also create <topic>.<group>.retry.1..3 (19.2: 10 s / 1 min / 10 min)
#              and <topic>.<group>.dlq, with the same partition count and 14 d retention (6.2).
#              Per group, so two services consuming one topic never re-read each other's
#              parked records (B10). List every service with a RetryTopicRouteBuilder on the
#              topic (scripts/test/test_platform_compose.sh checks it).
#
# MVP subset of the 6.2 catalogue. Deferred and therefore left out: the interop and
# compliance partner families, mw.compliance.instruction.v1, mw.recon.result.v1,
# dw.txn.event.v1.
